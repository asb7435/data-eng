## 1. 대상
- 원본: orders.csv (1,015행) — make_orders.py에서 시드 42로 생성
- 정제 결과: orders_clean.parquet (1,000행)
- 파이프라인: clean_orders.py (DuckDB 추출 + Pandas 정제)

## 2. 품질 지표 전후 비교
| 지표 | before | after |
|---|---|---|
| 행 수 | 1,015 | 1,000 |
| order_id 중복 | 15 | 0 |
| price 결측 | 30 (2.96%) | 0 (0.00%) |
| category 고유값 | 5 | 4 |

※ 중복 건수는 order_id의 첫 행을 제외한 추가 행 수이다.

## 3. 처리 내용과 근거
| 문제 | 처리 | 근거 |
|---|---|---|
| category 앞뒤 공백 20건 | str.strip() | ' 식품 '이 '식품'과 다른 값으로 집계되어 카테고리가 5가지로 나타났다. 공백 제거 후 식품·가전·의류·도서 4가지로 통일했다. |
| order_date 타입 | pd.to_datetime() | DuckDB로 읽으면 이미 날짜 타입이지만, pd.read_csv()로 읽은 데이터에도 같은 정제를 적용할 수 있도록 날짜 변환을 남겼다. |
| order_id 중복 15건 | drop_duplicates(subset='order_id', keep='first') | 동일 주문이 중복 집계되어 주문 수와 매출이 부풀려지는 것을 방지했다. 원본에서 먼저 등장한 주문을 유지했다. |
| price 결측 30건 | 중복 제거 후 중앙값 100,500원으로 보정 | 원본 결측률은 2.96%이며, 극단값의 영향을 덜 받는 중앙값을 사용했다. 중복 제거 전 중앙값은 101,000원으로 달라 중복 제거 후 보정했다. |
| 보정 후 주문 금액 | amount = price * quantity | 보정된 가격이 주문 금액에도 반영되도록 amount를 계산했다. |

## 4. 고치지 않은 것
- 실제 확인된 공백·중복·가격 결측은 모두 처리했다.
- 0 이하 가격·수량과 미지 카테고리는 정제 결과에서 각각 0건이었다. 이런 값은 임의로 보정하지 않고 파이프라인 검증에서 실패하도록 했다.
- 양수 가격의 이상치는 별도 기준이 없어 추가로 제거하거나 보정하지 않았다.

## 5. 검증
- 재실행 검증: 같은 원본을 두 번 읽고 clean()을 적용한 결과, equals()가 True였다.
- 저장 결과 검증: 새로 정제한 결과와 기존 orders_clean.parquet를 인덱스를 초기화한 뒤 비교한 결과, equals()가 True였다.
- 교차 검증: DuckDB로 정제 파일을 다시 측정한 결과, 1,000행·가격 결측 0건·주문 ID 중복 0건·카테고리 4가지로 Pandas 결과와 일치했다.
- 유효성 검사: 0 이하 가격·수량, 미지 카테고리, 중복 주문 ID, 가격 결측은 각각 0건이었다. 정제 파일의 모든 열에서 결측이 없었다.
- 금액 검증: amount와 price * quantity가 다른 행은 0건이었다.
- 날짜 검사: 주문일 범위는 2026-06-01~2026-07-30이며, 검증 기준일 2026-10-18보다 미래인 주문은 0건이었다.
- 검사기 자체 검증: 복사본에 price=-1000과 category='알수없음'을 각각 넣었을 때, clean_orders.py의 validate()와 validate_test.py 모두 가격 오류 1건·미지 카테고리 1건을 탐지했다.

## 6. 남은 과제
- 미래 날짜 검사는 validate_test.py에만 있으므로 clean_orders.py의 validate()에도 추가한다. 재현 가능한 검사를 위해 기준일을 인자로 받도록 개선한다.
- 현재 파이프라인은 price 결측만 검사하므로 order_id·customer_id·quantity·order_date의 필수값 누락도 검사한다.
- 같은 order_id인데 주문 내용이 다른 경우에도 첫 행만 남기므로, 중복 주문 간 내용이 같은지 확인하는 검사를 추가한다.
- 중앙값으로 보정한 가격은 실제 가격과 다를 수 있으므로 보정 여부를 별도 열로 남겨 매출 분석 시 구분한다.
- 검사기에 넣은 오류는 음수 가격과 미지 카테고리 두 종류이므로, 0 이하 수량·중복 ID·가격 결측·미래 날짜에 대한 탐지 테스트도 추가한다.
