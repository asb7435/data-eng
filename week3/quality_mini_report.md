## 3. 결측 처리 방식별 통계와 근거
공통으로 공백 제거 → 날짜 변환 → 주문 ID 중복 제거를 수행한 뒤, 가격 결측 처리만 바꿨다. 중앙값 방식은 100,500원으로 보정하고, 행 삭제 방식은 dropna(subset=['price'])로 30행을 삭제했다. 두 방식 모두 이후 amount를 다시 계산했다.

| 지표 | 중앙값 보정 | 행 삭제 |
|---|---:|---:|
| 행 수 | 1,000 | 970 |
| 평균 가격(원) | 100,420.00 | 100,417.53 |
| 가격 중앙값(원) | 100,500.00 | 100,500.00 |
| 가격 표준편차(원, 표본) | 56,077.19 | 56,938.63 |
| 평균 수량 | 2.9270 | 2.9381 |
| 평균 주문 금액(원) | 291,021.50 | 292,044.33 |
| 주문 금액 합계(원) | 29,102,150 | 28,328,300 |

행 삭제 시 중복 제거 후 주문의 3%가 사라지고, 금액 합계는 중앙값 방식보다 773,850원 줄었다. 평균 가격은 비슷하지만 평균 주문 금액은 오히려 증가했다. 삭제된 주문의 수량 구성이 다르기 때문에 가격 평균만으로 영향이 없다고 판단할 수 없다. 중앙값 보정은 가격 분산을 낮추고 추정 가격을 금액 합계에 반영한다. 어느 방식도 실제 누락 가격을 복원한 것은 아니므로 실제 매출의 정답이라고 볼 수는 없다.

## 4. events.parquet 품질 — DuckDB SQL
100만 행의 품질 측정을 EVENT_SQL에 작성했다. count, count(DISTINCT), FILTER, min, max로 집계하고, Python은 쿼리 실행·시간 측정·저장만 담당한다. 비교용 Pandas 집계는 같은 결측·중복 정의를 사용한다.

| 지표 | 결과 |
|---|---:|
| 행 수 | 1,000,000 |
| event_id 중복 | 0 |
| event_id / user_id / event_type / value / ts 결측 | 각각 0 |
| 이벤트 종류 수 | 3 |
| user_id 0 이하 | 0 |
| value 0 이하 | 0 |
| view·cart·buy 외 미지 이벤트 | 0 |

이벤트 시각은 2026-06-01 00:00:02~2026-07-30 23:59:59였다. 이벤트 중복은 event_id의 결측을 제외한 추가 중복 건수이며, ID 결측은 별도 열로 측정한다.

## 5. 실행 시간 비교와 검증
| 방식 | 5회 중앙값(초) | 최소(초) | 최대(초) |
|---|---:|---:|---:|
| DuckDB SQL | 0.037331 | 0.033766 | 0.040228 |
| Pandas | 0.081833 | 0.064472 | 0.083625 |

- 측정 범위: Parquet 읽기 + 전체 품질 집계 + 결과 반환. CSV 저장과 출력은 제외했다. DuckDB 연결 생성과 라이브러리 import도 제외했다.
- 두 방식 모두 1회 워밍업 후 각 5회 측정했다. 매 회차 실행 순서를 번갈아 적용했다.
- DuckDB는 SQL 결과를 fetchone()으로 반환하고, Pandas는 pd.read_parquet()로 읽은 뒤 집계한다. DuckDB의 결과를 Pandas로 변환하는 비용은 넣지 않았다.
- 매 회차 두 방식의 모든 품질 지표가 같은지 assert로 확인했고 모두 통과했다.
- 이 환경의 중앙값 기준 DuckDB가 약 2.19배 빨랐다. 파일 캐시가 반영된 반복 측정이며, 최초 읽기 성능이나 모든 환경에 일반화할 수 있는 결과는 아니다. 스레드 설정은 각 라이브러리 기본값을 사용했다.
